# Feedback Loop

기본 흐름은 요구사항 요약 → 설계 제안 → 사용자 승인 → 구현 → 검증 → 결과 보고다.

사용자가 명시적으로 오토모드를 요청한 경우 기본 흐름은 요구사항 요약 → 실행 계획 수립 → 구현 → 검증 → 피드백 반영 → 재검증 → 결과 보고다. 이때 초기 목표, 범위, 금지영역을 사용자 승인으로 간주하고 중간 승인 없이 진행한다.

- 불명확하면 구현 전에 질문한다.
- 설계에는 수정 파일, 방식, 리스크, 검증 방법을 포함한다.
- 일반 모드에서는 승인 전 파일을 수정하지 않는다.
- 오토모드에서는 승인 대기 없이 수정하되, 작업 로그와 검증 결과를 남긴다.
- 작업 중 범위 확대, 파괴적 작업, 비밀값 처리, 배포 실행, 외부 서비스 과금/운영 영향이 필요하면 멈추고 보고한다.
- 멀티에이전트를 사용할 때는 백엔드, 프론트엔드, 검증, 문서처럼 역할을 나누고 최종 결정과 수정 책임은 현재 에이전트가 가진다.
- 결과 보고에는 수정 파일, 변경 내용, 검증 여부를 적는다.
